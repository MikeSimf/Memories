# DnD Memory — паспорт проекта

## 1. Назначение

**DnD Memory** — память настольной ролевой кампании. Приложение хранит героев
партии, встреченных персонажей, локации, предметы, истории сессий и материалы,
связывает их ссылками и позволяет работать даже без интернета.

Основная идея: мастер и игроки не теряют детали между сессиями. Любое имя в
описании можно превратить в ссылку `[[Имя объекта]]`, а карточка показывает,
кто на кого ссылается.

### Для кого

- **Мастер** — ведёт кампанию, заводит персонажей, локации, предметы и истории.
- **Игрок** — ведёт своего героя, пишет истории, смотрит общий справочник.
- **Наблюдатель** — только смотрит материалы кампании.

### Что решает

- единый справочник вместо заметок в разных файлах и чатах;
- быстрый переход по упоминаниям;
- совместная работа с разными правами;
- офлайн-работа на телефоне с последующей синхронизацией;
- отдельные тестовый и рабочий контуры.

## 2. Основные возможности

- Кампании с участниками и ролями.
- Шесть разделов: **Персонажи, Локации, Предметы, Герои, Истории, Материалы**.
- Карточки объектов с аватаром, описанием, ссылками и упоминаниями.
- Живые ссылки `[[Имя]]` и `[[Имя|подпись]]`, безопасное создание объекта по ссылке.
- Поиск по активному разделу и по всей кампании, в том числе офлайн.
- Истории: черновик хранится только на устройстве, публикация уходит на сервер.
- Приглашения по QR-коду и по одноразовой ссылке.
- Роли: владелец, мастер, игрок, наблюдатель.
- Передача кампании мастеру.
- Справочники кампании: разрешённые расы, классы, типы предметов и локаций.
- Обратная связь и отчёты о падениях приложения.
- Административный кабинет `system`.

## 3. Структура репозитория

| Каталог | Назначение | Технологии |
|---|---|---|
| `server/` | HTTP API, бизнес-логика, синхронизация, БД | Java 11, Spring Boot 2.7, PostgreSQL 15, Flyway, JWT, Maven |
| `web/` | Веб-версия и PWA | Vue 3, TypeScript, Vite, Pinia, IndexedDB, Service Worker |
| `android/` | Мобильное приложение | Java, Room, Retrofit, WorkManager, MVVM |
| `deploy-kit/` | Готовое развёртывание без исходников | Docker Compose, nginx, два контура |
| `docs/` | Архитектура, API, модель данных, роли, синхронизация | Markdown |
| `scripts/` | Сборка, релизы, установка | Bash |

Репозиторий: `https://github.com/MikeSimf/Memories`, ветка `main`.

## 4. Архитектура

```
Клиенты (web PWA, Android)
        │  HTTPS, JWT
        ▼
nginx (хост) ──► web-контейнер (статика + /api)
                        │
                        ▼
                 Spring Boot API
                        │
                        ▼
                   PostgreSQL
```

- **Сервер** — единственный источник истины, хранит объекты, участников,
  журнал изменений и ревизии.
- **Веб** — SPA/PWA: локальная копия в IndexedDB, синхронизация через HTTP.
- **Android** — локальная база Room, очередь неотправленных правок, WorkManager.
- **Синхронизация** — по журналу изменений кампании; конфликты разрешаются
  по ревизиям и показываются пользователю.

Подробнее: [`architecture.md`](architecture.md), [`sync.md`](sync.md),
[`data-model.md`](data-model.md), [`api.md`](api.md).

## 5. Роли и права

| Роль | Возможности |
|---|---|
| **Владелец** | всё в кампании, передача кампании, удаление, управление участниками |
| **Мастер** | редактирует любые объекты и истории, управляет справочниками; удалить кампанию не может |
| **Игрок** | редактирует своего героя, пишет истории от любого лица, смотрит справочник |
| **Наблюдатель** | только просмотр |

Правила и жизненный цикл участника: [`roles.md`](roles.md).

## 6. Данные

Основные сущности:

- `users`, `refresh_tokens`, `devices`;
- `campaigns`, `members`, `invites`;
- `heroes`, `characters`, `locations`, `items`;
- `retellings`, `materials`, `files`;
- `change_log` — журнал синхронизации;
- `feedback`, `crash_reports`;
- `races`, `character_classes`, `item_types`, `location_types`;
- `campaign_dictionary_disabled` — запрещённые значения справочников;
- `card_templates`, `card_blocks` — конструктор карточек (в списках временно отключён).

Схема и связи: [`data-model.md`](data-model.md).

## 8. Сборка и релиз

- Сервер: `mvn -o package -DskipTests`.
- Веб: `npm run build` → `web/dist`.
- Android: flavor `prod` (`ru.dndmemory`) и `qa` (`ru.dndmemory.test`).
- Комплекты: `prod-kit.tar.gz`, `test-kit.tar.gz`.
- Обновление — только своим тегом; общий `update-from-release.sh` больше не используется.

Подробнее: [`deploy-kit/README.md`](../deploy-kit/README.md).

## 9. Офлайн-режим

- Приложение показывает локальные данные сразу, без ожидания сети.
- Сетевые запросы выполняются только при наличии интернета.
- Изменения сохраняются локально и уходят в очередь.
- При появлении сети выполняется синхронизация, конфликты показываются пользователю.
- Если объект создан офлайн с расой, которую later запретили в справочнике,
  сервер заменяет значение на «Неизвестно».

## 10. Безопасность

- JWT access/refresh, пароли — BCrypt.
- Роли проверяются на сервере, клиентские проверки только для интерфейса.
- Приглашения одноразовые, с ограниченным сроком.
- Ссылки сбрасываются вручную через кабинет `system`.
- Файлы доступны только авторизованным участникам кампании.
- Пароль и токены не пишутся в логи.

## 11. Администрирование

Служебная учётка **`system`**:

- видит все кампании, не отображается в участниках;
- в карточках как автор изменений показывается **«Администратор»**;
- кабинет `/admin`: пользователи, обратная связь, ошибки, справочники;
- `/admin/cards` — конструктор карточек (пока отключён в списках);
- `/admin/dictionaries` — глобальные справочники;
- генерация ссылок сброса пароля.

## 12. Статус проекта

**Рабочий проект для личного использования.** Прод и тест обновляются вручную,
автоматического CI/CD и внешнего мониторинга нет.

Известные ограничения:

- в Android списки рас/типов пока не фильтруются по справочнику кампании;
- конструктор карточек временно не применяется к спискам;
- загрузка своих иконок для справочников не реализована;
- карточки открытой сущности (`DETAIL`) не реализованы.

# Что проверено, а что нет

Честный отчёт о проверках: в окружении, где писался проект, **нет Docker, JDK по
умолчанию и Android SDK**, поэтому часть проверок выполнена кодом и статическим
анализом, а не запуском. Ниже — что именно проверено и как повторить проверку у себя.

## Сервер приложений — проверено запуском

| Проверка | Команда | Результат |
|---|---|---|
| Компиляция всех исходников | `cd server && mvn -DskipTests package` | Успешно, `target/dnd-memory-server.jar` (43 МБ) |
| Юнит-тесты прав ролей | `mvn test` → `PermissionServiceTest` | 5 тестов, все зелёные |
| Юнит-тесты ссылок `[[…]]` | `mvn test` → `WikiLinkServiceTest` | 5 тестов, все зелёные |
| Сборка Spring-контекста целиком | `mvn test` → `ApplicationContextTest` | Успешно: нет циклических зависимостей, все бины на месте, настройки привязываются |
| Соответствие JPA-маппинга SQL-схеме | `node scripts/check-schema.mjs` | 10 таблиц, каждая колонка замаплена, лишних нет |
| Найденные и исправленные дефекты | — | `NPE` при разборе пустого списка текстов; циклическая зависимость `MemberService ↔ InviteService`; нестабильная пагинация в `snapshot` без сортировки |

`ApplicationContextTest` поднимает приложение на H2 с выключенным Flyway: он
доказывает, что контекст собирается, но **не** проверяет SQL-миграции на настоящем
PostgreSQL. Для этого есть `./scripts/run-integration-tests.sh` (нужен Docker) —
запустите его у себя перед первым развёртыванием.

## Что проверено статически

* **Веб-версия** — сборка и проверка типов (`npm run build`, `vue-tsc --noEmit`)
  выполнялись; результат указан в [`web/README.md`](../web/README.md).
* **Android** — компилятора в окружении нет, поэтому вместо сборки выполнена сверка
  ссылок: `node scripts/check-android.mjs` проверяет, что все `R.id`, `R.string`,
  `R.layout`, `R.drawable`, `R.menu` из Java существуют, что ссылки `@string/…`,
  `@drawable/…`, `@style/…` в макетах разрешаются, а активности из манифеста есть в
  исходниках. Скрипт написан специально для этого проекта и запускается из корня
  репозитория.
* **Docker-конфигурация** — файлы `compose.test.yml`, `compose.prod.yml`,
  `Dockerfile.server`, `Dockerfile.web` и конфиги nginx написаны, но **не запускались**:
  `docker` в этом окружении отсутствует. Первый `./scripts/deploy.sh test` на вашем
  сервере — это и есть их настоящая проверка.

## Чего точно не проверено

1. **Первый старт на PostgreSQL.** Миграция `V1__init.sql` не выполнялась на живой
   базе. Синтаксис проверен вычиткой, сверка с JPA-маппингом пройдена, но реальный
   `flyway migrate` нужно увидеть своими глазами.
2. **Полный цикл синхронизации двух устройств.** Логика push/pull и разрешения
   конфликтов покрыта кодом и документацией [`sync.md`](sync.md), но сценарий
   «телефон офлайн → правка → сервер → второй телефон» не воспроизводился.
3. **Сборка APK.** Android-проект не собирался ни разу.
4. **Внешние входы Яндекс и VK.** Код обмена кода на токен написан, но без
   зарегистрированных приложений и реальных `client_id` не выполнялся ни один запрос
   к провайдерам.
5. **TLS и nginx.** Сертификат Let's Encrypt и конфиг `nginx.prod.conf.template`
   не проверялись в бою.

## Порядок первой проверки у себя

```bash
# 1. Сервер: полный прогон с настоящей базой (нужен Docker)
./scripts/run-integration-tests.sh

# 2. Тестовый контур
sudo bash scripts/install-docker.sh
cp docker/env.test.example docker/env.test && nano docker/env.test
./scripts/deploy.sh test
curl http://localhost:8081/api/health          # {"status":"UP",...}

# 3. Веб-версия в браузере: http://<сервер>:8081
#    Зарегистрируйтесь, создайте кампанию, добавьте объект со ссылкой [[Имя]],
#    проверьте переход по ссылке и поиск.

# 4. Android: собрать в Android Studio, указать DND_API_BASE_URL на тестовый контур,
#    проверить офлайн: выключить интернет, создать объект, включить интернет,
#    убедиться, что правка ушла на сервер (индикатор синхронизации).
```

Если на шаге 1 или 2 что-то падает — пришлите текст ошибки: по нему правка обычно
одна-две строки.

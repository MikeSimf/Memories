# DnD Memory — веб-версия (PWA)

Клиентская SPA справочника настольной сессии D&D: герои, персонажи, локации,
предметы, пересказы сессий и живая навигация по упоминаниям `[[Имя]]`.
Работает офлайн: данные лежат в IndexedDB, локальные правки уходят на сервер
при появлении сети.

Контракт — `../docs/api.md`, `../docs/sync.md`, `../docs/roles.md`,
`../docs/architecture.md` (раздел 4).

## Стек

| Слой | Технология |
|---|---|
| Фреймворк | Vue 3 (`<script setup>`, TypeScript) |
| Сборка | Vite 6 |
| Состояние | Pinia |
| Маршруты | vue-router 4 |
| Локальная база | `idb` (IndexedDB) |
| PWA | `vite-plugin-pwa` (Workbox, app shell) |
| Разметка описаний | `markdown-it` + `dompurify` |
| QR | `qrcode` (генерация), `jsqr` + `BarcodeDetector` (сканирование) |

## Запуск

```bash
npm install       # установка зависимостей
npm run dev       # дев-сервер Vite (http://localhost:5173)
npm run build     # проверка типов + продакшн-сборка в dist/
npm run typecheck # только проверка типов (vue-tsc --noEmit)
npm run preview   # локальный просмотр собранной статики
```

Сборка — статические файлы в `dist/`, их раздаёт nginx из docker-compose
(`docker/compose.prod.yml`). Для дев-режима без отдельного домена есть прокси:
запросы `/api` уходят на `VITE_DEV_PROXY_TARGET` (по умолчанию
`http://localhost:8080`).

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `VITE_API_BASE_URL` | Базовый адрес API. Пусто — относительные запросы `/api/...`, как за nginx | пусто |
| `VITE_DEV_PROXY_TARGET` | Куда проксировать `/api` в `npm run dev` | `http://localhost:8080` |

Пример — `.env.example`.

## Структура каталогов

```
src/
  api/         HTTP-клиент: types.ts (модели из docs/api.md), client.ts (Bearer,
               автообновление по 401 с повтором), endpoints.ts, errors.ts,
               tokens.ts (хранение токенов, идентификатор установки)
  db/          локальная база IndexedDB: schema.ts (хранилища и типы записей),
               entities/retellings/members/campaigns/pending/syncState — репозитории,
               search.ts — локальный поиск
  sync/        офлайн-синхронизация: engine.ts (push → pull → snapshot, конфликты,
               автосинхронизация), queue.ts (очередь правок), payload.ts
  stores/      Pinia: auth, campaigns, campaign (активная кампания), sync, ui
  router/      маршруты и охранник авторизации
  components/  переиспользуемые компоненты (шапка, формы, модалки, QR, разметка)
  views/       экраны
  utils/       wikilinks, markdown, permissions, attrs, datetime, qr, uuid, debounce
  types/       типы форм, общие для экранов и сторов
  styles/      токены темы, тёмная и светлая схемы, компоненты
```

Разделение намеренное: экраны и компоненты не ходят в сеть напрямую, они
работают со сторами, сторы — с локальной базой и sync-движком, а сеть живёт
только в `src/api`.

## Офлайн-режим

### Схема локальной базы (`docs/sync.md` §4)

| Хранилище | Ключ | Содержимое |
|---|---|---|
| `entities` | `id` | объекты кампании + `dirty` (0/1) и `conflict` |
| `retellings` | `id` | опубликованные пересказы (только `PUBLISHED`) |
| `retelling_drafts` | `id` | черновики пересказов, **только на устройстве** |
| `pending_changes` | `clientChangeId` | очередь неотправленных правок (`baseRevision`, `payload`, `attempts`) |
| `sync_state` | `campaignId` | `lastPulledRevision`, `lastSyncAt`, `lastError`, признак загрузки snapshot |
| `members` | `id` | участники и их роли (кэш для офлайна) |
| `campaign` | `id` | карточка кампании: роль, права, счётчики, ревизия |
| `meta` | `key` | служебные значения |

Индексы (`campaignId`, `[campaignId, type]`, `[campaignId, objectId]`) позволяют
читать данные одной кампании без полного перебора.

### Цикл синхронизации

1. **PUSH** — `POST /api/campaigns/{id}/sync/changes` с телом
   `{ clientId, changes: [...] }`. Локальные правки схлопываются по объекту
   (payload — полное состояние объекта), `clientChangeId` служит ключом
   идемпотентности.
2. **PULL** — `GET .../sync/changes?since={lastPulledRevision}&limit=500`;
   при `hasMore: true` запрос повторяется. Изменения по объектам с
   неотправленными локальными правками не применяются: локальная версия уйдёт
   на сервер следующим push.
3. **SNAPSHOT** — `GET .../sync/snapshot?limit=&cursor=` при первом входе на
   устройстве и при `410 resync_required` (журнал изменений скомпактирован).
   Клиент проходит по курсорам, затем сохраняет `lastPulledRevision` и удаляет
   локальные записи, которых нет в снапшоте (кроме «грязных»).

### Конфликты

Результат каждой правки разбирается по `status`:

| `status` | Что делает клиент |
|---|---|
| `APPLIED` | снимает `dirty`, сохраняет серверную ревизию |
| `CONFLICT_RESOLVED` | то же + уведомление «ваша версия новее, конфликт в вашу пользу» |
| `REJECTED` | убирает правку из очереди, сохраняет `conflict.server` и показывает баннер с выбором: «оставить серверную версию» или «перезаписать своей» (повторный push с новым `updatedAt`) |

### Когда запускается

Старт приложения, событие `online`, отложенный запуск через 3 секунды после
локальной правки, кнопка «Синхронизировать» в шапке (индикатор состояния),
таймер раз в 5 минут при открытой вкладке — таблица из `docs/sync.md` §5.

### Черновики пересказов

Черновик живёт в `retelling_drafts` и не попадает ни в `pending_changes`, ни в
push. Кнопка «Опубликовать» переводит его в `PUBLISHED`: запись переезжает в
`retellings` с `dirty = 1` и уходит в очередь как `UPSERT`. В интерфейсе
черновики помечены бейджем «Черновик» и существуют только на том устройстве,
где созданы.

## Разметка описаний

Поддерживается markdown и ссылки `[[Имя]]`, `[[Имя|подпись]]`,
`[[#uuid|подпись]]`. Имена разрешаются по локальной базе кампании без учёта
регистра (при неоднозначности — первый по алфавиту, как на сервере). Клик по
разрешённой ссылке открывает карточку объекта, неразрешённая рисуется
пунктиром и предлагает создать объект с таким именем. HTML проходит через
DOMPurify, разметка из данных не может внедрить скрипт.

## PWA

`vite-plugin-pwa` собирает манифест (имя «DnD Memory», тёмная тема, иконки SVG,
включая maskable) и service worker: app shell кэшируется, поэтому приложение
открывается без сети, а данные приходят из IndexedDB. Изображения объектов
(`/api/files/...`) кэшируются стратегией stale-while-revalidate.

## Права

Интерфейс опирается на `myPermissions` из `GET /api/campaigns/{id}`, а при
отсутствии связи — на локальное зеркало матрицы ролей из `docs/roles.md`
(`src/utils/permissions.ts`). Сервер остаётся источником истины: он проверяет
права при каждой записи, клиент лишь не показывает недоступные действия.
